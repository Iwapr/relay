# Relay 0.2.0：局域网默认部署与远程管理

首次 `npm run setup` 默认选择本机唯一的私有 IPv4 网卡，关闭 Tailscale 和公网入口。多网卡通过 `--host` 选择地址；保留 `--host 127.0.0.1` 本机模式。不会绑定 `0.0.0.0`。已有配置不自动迁移，重复 setup 保留账号、项目和网络设置。

右上角菜单在「账号管理」下面新增「远程管理」窗口，支持检测 Tailscale、实时启用和关闭独立远程监听，并可生成云服务器 Nginx HTTPS 中转指引。修改远程设置需要已登录、Origin / CSRF 校验，且必须通过本机或局域网入口操作。

## 简易安装与界面演示

新增 `./install.sh`：自动准备私有 Node.js 24、锁定版本的官方 Codex CLI、项目依赖、局域网配置和可用的 systemd 用户服务。`./relay` 提供启动、停止、状态、日志和登录信息入口。安装器不自动执行 sudo，也不覆盖已有配置；没有 systemd 时使用前台模式。

README 简化为安装、演示和常用操作入口；原有详细说明完整迁入 [使用手册](../manual.md)。新增电脑端和手机端截图及 GIF，全部来自隔离演示数据，可通过 `npm run docs:media` 重录。

## 安装

从 GitHub clone 后，在项目目录使用普通 Linux 用户执行：

```bash
./install.sh
```

源码包同样可用：

```bash
sha256sum -c remote-workbench-0.2.0.tar.gz.sha256
mkdir relay-0.2.0
tar -xzf remote-workbench-0.2.0.tar.gz -C relay-0.2.0
cd relay-0.2.0
./install.sh
```

所需基础系统工具、安装选项、后台运行与恢复步骤见 [快速安装](../quickstart.md)。发行包不包含账号凭据、运行数据或 node_modules。原手动部署方式仍可使用。

## 远程访问

1. 在局域网访问工作台，打开「远程管理」。
2. 管理员按窗口指引在办公室服务器安装并登录 Tailscale。此步骤需要系统权限和官方登录授权，网页不会执行 sudo。
3. 刷新检测，启用 Tailscale 并保存。远程设备安装 Tailscale 即可访问。
4. 若需要免客户端访问，选择云服务器中转；填写公网 IPv4、域名、HTTPS 端口、云端 Tailscale IPv4，生成云端安装步骤。当前向导要求域名，使用 Certbot 签发证书并配置自动续期。
5. 在云端执行指引并保存窗口配置，通过 HTTPS 地址验证网站登录、对话流式输出和文件访问。

已有 Nginx 的云端可复用现有服务，应避免重复的同域名、同端口站点；其他服务占用入口端口时需先解决冲突。端口 80 保留给 Certbot HTTP-01 验证。办公室无需端口映射。Tailscale 访问控制建议只允许云端访问本实例业务端口。

## 升级及限制

先备份当前私有配置及数据库，再使用新源码构建。保留原 `.runtime` 或独立配置路径，在任务空闲时重启相应服务。不要用新 setup 覆盖旧配置；不要将凭据复制进发行包。由外部实例描述文件强制设置公网域名的部署保持管理员管理，窗口只读。

保存远程配置不重启 Agent 或主入口。关闭远程入口会断开远程网页连接，但不停止后台任务。监听失败不会写入新的配置。云端系统命令由管理员执行，本版本不会自动登录云服务器；实际公网连通性和证书签发需在目标环境验证。
